# natural-korean-skills-for-research

**AI와 CS 연구자를 위한 한국어 문체 스킬.** 논문 정리, 실험 노트, 기술 문서, 코드 리뷰, 동료에게 하는 개념 설명을 번역투 없는 한국어로 씁니다. 기술 용어는 영문 그대로 두고 문장 골격만 한국어로 씁니다.

*A Claude Code skill for AI/CS researchers writing Korean. It strips translationese from the sentence frame while keeping technical terms in English, so your notes stay searchable against the original papers.*

---

## 왜 필요한가

LLM이 쓴 한국어는 대개 문법이 틀리지 않습니다. 맞춤법 검사기를 돌려도 깨끗합니다. 그런데 읽으면 뻣뻣합니다.

> 이러한 변화는 효율성의 향상을 가져올 수 있습니다.

주어는 추상명사, 동사는 "가져오다", 목적어는 명사로 굳은 동작입니다. 영어 *This change can bring an improvement in efficiency*의 골격을 그대로 옮긴 문장입니다. 한국어를 모국어로 쓰는 사람은 이렇게 쓰지 않습니다.

> 이렇게 바꾸면 효율이 올라갑니다.

문제가 철자가 아니라 문장의 골격이라서 맞춤법 검사기로는 잡히지 않습니다.

연구 글에는 문제가 하나 더 붙습니다. **용어**입니다. `attention`을 `어텐션`으로 적어 두면 문장은 한국어다워지지만 원문 논문과 이어지지 않고, 독자가 검색할 때 한 번 더 번역해야 합니다. 반대로 문장 골격까지 영어를 끌고 오면 이런 글이 됩니다.

> model을 3 epoch 동안 train했고, data는 clean한 subset만 썼다.

한국어 조사를 붙인 영어 문장입니다. 이 스킬은 두 실패 사이에 선을 긋습니다.

## 무엇을 근거로 만들었나

번역투 판정과 용어 분류를 취향으로 정하지 않으려고 다음 자료를 확인했습니다.

| 자료 | 무엇을 가져왔나 |
|---|---|
| [Google 머신러닝 용어집 한국어판](https://developers.google.com/machine-learning/glossary?hl=ko) | AI 용어를 영문 유지(ReLU, BERT, GAN, TPU), 한글 음차(어텐션, 임베딩, 레이어, 토큰), 한국어 번역(과적합, 손실, 정규화, 경사하강법) 세 갈래로 나눠 쓴다는 사실. **3층 용어 분류**가 여기서 나왔습니다 |
| [쿠버네티스 한글화 모범 사례](https://kubernetes.io/ko/docs/contribute/localization_ko_best_practice/) | 영문 병기는 문서에서 처음 등장할 때 한 번만, 한 페이지 안에서 같은 단어는 일관되게. **병기 규칙**의 근거입니다 |
| 국내 학회의 국문 논문 투고 규정 | 통일된 역어가 없는 외래 용어는 한글 역어를 쓰고 괄호에 원어를 부기하는 것이 원칙. 이 스킬의 용어 규칙과 충돌하므로 **투고 원고를 범위에서 뺐습니다** |
| 국내 학술 글쓰기 지침 ([SNU](https://libguide.snu.ac.kr/c.php?g=321578&p=6684647) 등) | 논문에서 1인칭을 줄이고 `필자는` 대신 `본 연구는`을 권하는 관행. `본 연구`를 격식 한자어로 깎아내지 않는 근거입니다 |
| [국립국어원 표준 전문용어](https://www.korean.go.kr/front/imprv/stndrdList.do?mn_id=159), [온라인가나다](https://korean.go.kr/front/mcfaq/mcfaqView.do?mn_id=62&mcfaq_seq=9129) | 정부 고시 표준 용어와 외래어 표기 기준. `퍼센트`와 `퍼센트포인트`의 구분 |
| [TTA 정보통신용어사전](https://terms.tta.or.kr/) | 국내 정보통신 분야 표준 용어 |
| [KatFishNet](https://arxiv.org/abs/2503.00032) (Park, Kim, Kim & Han) | 한국어 LLM 텍스트를 사람 글과 가르는 지표로 **띄어쓰기, 품사 다양성, 쉼표 사용**을 지목한 논문 |
| 국내 AI와 CS 기술 블로그, 논문 리뷰 글 | 실제 용법 관찰. "Attention 레이어", "LoRA", "loss 수렴", "tail latency"처럼 영문 기법명과 한글 음차, 한국어 서술이 섞인 형태가 일반적입니다 |

한 가지 밝혀 둡니다. **Google 용어집은 attention을 음차(`어텐션`)로 적지만, 이 스킬은 영문 유지(`attention`)를 기본으로 합니다.** 용어집은 개념을 처음 배우는 독자를 향하고, 이 스킬은 원문 논문과 코드를 함께 읽는 독자를 향하기 때문입니다. 입문자가 섞인 글이라면 `어텐션(attention)` 병기 쪽이 맞고, 스킬도 그 규칙을 함께 담고 있습니다.

국내에 AI와 CS 분야 표기를 확정한 단일 표준은 없습니다. 3층 분류는 관행을 정리한 것이지 규범이 아닙니다.

## Before / After

### 논문 정리

| | |
|---|---|
| **Before** | 이 논문은 대규모 언어 모델의 추론 능력 향상을 위해 사고의 연쇄 기법을 제안한다. 제안된 방법은 모델로 하여금 중간 추론 단계를 생성하도록 유도함으로써, 복잡한 산술 문제에 대한 정확도를 크게 향상시킬 수 있다. |
| **After** | 이 논문은 LLM의 추론 능력을 끌어올리는 방법으로 chain-of-thought를 제안한다. 모델이 답을 바로 내지 않고 중간 단계를 먼저 쓰게 만드는 방식이다. 복잡한 산술 문제에서 정확도가 크게 올랐다. |

`사고의 연쇄`로 번역하면 원문 대조가 끊깁니다. 한 문장을 세 개로 나눈 이유는 영어 요약문의 겹친 관계절을 한국어가 받아내지 못하기 때문입니다.

### 실험 결과

| | |
|---|---|
| **Before** | 본 실험에서는 어텐션 메커니즘에 기반하여 모델을 파인튜닝하였으며, 그 결과 베이스라인 대비 정확도가 70%에서 72%로 2% 향상되었음을 확인할 수 있었다. 이러한 결과는 해당 기법이 효과적임을 시사하는 바가 크다. |
| **After** | 이 실험에서는 attention 기반 모델로 fine-tuning을 했다. 정확도는 baseline의 70%에서 72%로 2%p 올랐다. 이 기법이 통한다는 신호로 볼 만하다. |

두 가지를 보세요.

**`%`와 `%p`.** 원문의 "2% 향상"은 틀린 표기입니다. 백분율 수치가 2만큼 움직였으므로 `2%p`입니다. 문체가 아니라 사실 문제입니다.

**확신의 세기.** 원문의 `시사하는 바가 크다`는 확신을 다 주지 않는 표현이고, 고친 글의 `볼 만하다`도 같은 세기입니다. "효과적이다"로 단언하면 다듬기가 아니라 다른 주장입니다. 없던 수치도 넣지 않습니다.

### 성능 분석 메모

| | |
|---|---|
| **Before** | 서비스의 응답 지연은 데이터베이스 커넥션 풀의 고갈에 의해 발생되어지는 것으로 분석되었으며, 이를 통해 tail latency가 악화되는 결과를 가져왔습니다. 커넥션 풀 사이즈의 증가를 통해 개선이 가능할 것으로 판단됩니다. |
| **After** | 응답 지연은 DB 커넥션 풀이 말라서 생긴다. 그래서 tail latency가 나빠졌다. 커넥션 풀을 키우면 나아질 것으로 보인다. |

`발생되어지는`은 이중 피동이라 한국어 어문 규범에서 비문으로 봅니다. 마지막 문장의 `~로 보인다`는 그대로 뒀습니다. 아직 고쳐 보지 않았으니 단언할 근거가 없습니다.

### 코드 리뷰

| | |
|---|---|
| **Before** | 이 함수는 동시성 이슈를 가지고 있는 것으로 보여집니다. 두 개의 스레드에 의해 동시에 호출될 경우, race condition이 발생될 가능성이 존재합니다. 락을 통한 보호가 필요할 것으로 사료됩니다. |
| **After** | 이 함수는 동시성 문제가 있어 보입니다. 스레드 두 개가 동시에 부르면 race condition이 납니다. `lock`으로 막아야 합니다. |

`race condition`은 1층이라 영문으로, `스레드`는 2층이라 한글로 뒀습니다. `lock`은 코드에서 부르는 이름이라 백틱으로 감쌌습니다.

더 많은 예시와 **고치면 안 되는 경우**는 [`examples/before-after.md`](examples/before-after.md)에 있습니다.

## 이 스킬이 하는 일

1. **한국어 어순으로 씁니다.** 영어 문장을 머릿속에서 옮겨 적지 않습니다. 옮겨 적은 문장은 나중에 되돌릴 수 없습니다.
2. **반드시 고치는 것을 고칩니다.** 이중 피동, `~에 있어서`, `가지고 있다`, 영어식 피동, 추상 주어 + 만능 동사, 명사화, 결말 관용구(`결론적으로`, `시사하는 바가 크다`), 조사 번역투 쏠림, `~적 N` 체인, 연결어미 뒤 쉼표, 3박자 반복. 전부 어느 어절이 어겼는지 손으로 짚을 수 있는 규칙입니다.
3. **판단이 필요한 것은 방향만 잡습니다.** 문장 리듬, 문장 길이, 주어 생략, 지시어 절제, 복수 `-들`, 한자어 낮추기, 불릿 절제.
4. **사실을 바꾸지 않습니다.** 수치, 날짜, 고유명사, 인용문, 인과의 방향, **확신의 세기**를 그대로 둡니다. 읽기 좋아지려고 원인이나 빈도를 지어내면 다듬기가 아닙니다.
5. **기본 출력은 한국어 본문뿐입니다.** 규칙 이름이나 위반 건수를 붙이지 않습니다. "뭘 고쳤어?"라고 물으면 그때 before/after 표를 냅니다.

### 용어 정책

판단 기준은 하나입니다. **논문과 코드에서 그 형태로 쓰이는가, 아니면 한국어에 이미 들어온 말인가.**

| 층 | 표기 | 예 |
|---|---|---|
| 1층 | 영문 그대로 | attention, fine-tuning, loss, gradient, baseline, ablation, throughput, deadlock, race condition, garbage collection |
| 2층 | 한글 음차 | 모델, 데이터, 파라미터, 레이어, 벡터, 알고리즘, 라이브러리, 캐시, 스레드, 커널 |
| 3층 | 한국어 단어 | 학습, 추론, 성능, 정확도, 가중치, 수렴, 실험, 평가, 한계, 지연, 병목 |

머신러닝뿐 아니라 운영체제와 동시성, 네트워크와 분산 시스템, 데이터베이스, 프로그래밍 언어와 컴파일러, 보안, HCI 분야의 목록을 함께 담았습니다. 전체 목록, 조사 결합 규칙, 같은 단어가 두 뜻인 경우(`bias` 대 `편향`, `queue` 대 `줄`)는 [`references/term-policy.md`](references/term-policy.md)에 있습니다.

### 연구 글의 관습

문체 규칙을 기계적으로 밀어붙이면 오히려 어색해지는 자리를 따로 다룹니다.

- `본 연구`는 국문 논문의 권장 표현이라 그대로 둡니다. 실험 노트나 블로그라면 `이 연구`가 자연스럽습니다.
- "이 효과는 X에 의해 매개된다" 같은 학술 정형 피동은 유지하고, "저자들에 의해 제안된"처럼 행위자가 이미 문장에 있는 피동만 능동으로 고칩니다.
- `%`와 `%p`, 소수점, 유효숫자, 수식 기호에 붙는 조사.
- 번호 인용(`[12]는`), 저자 인용(`Vaswani 등(2017)`), `그림 1`과 `표 2`.

근거와 함께 [`references/writing-conventions.md`](references/writing-conventions.md)에 정리했습니다.


## 사용법

한국어로 쓰거나 다듬어 달라고 하면 걸립니다.

```
이 논문 한국어로 정리해 줘
실험 결과 노트로 써 줘
번역투 빼고 다시 써 줘
이 설계 문서 한국어로 써 줘
이거 자연스러운 한국어로 설명해 줘
```

기본 출력은 한국어 본문뿐입니다. 무엇을 고쳤는지 보려면 `뭘 고쳤어?`, `before/after 보여줘`, `어떤 규칙이야?`를 덧붙이세요.

## 범위와 한계

**맞습니다**: 논문 정리와 리뷰, 실험 노트, 결과 보고, 기술 문서, 설계 문서, 코드 리뷰, 이슈와 PR 설명, 기술 블로그, 동료에게 하는 개념 설명. 영어 자료를 읽고 한국어로 정리하는 일. 번역투가 가장 많이 새어 들어오는 자리입니다.

**맞지 않습니다**:

- **학회 투고용 국문 논문 원고.** 국내 학회 규정은 대체로 한글 역어를 본문에 쓰고 원어를 괄호에 병기하도록 합니다. 이 스킬의 용어 규칙과 충돌하므로 투고 원고는 학회 지침을 따르세요.
- 입문자나 비전공자를 대상으로 하는 글. 영문 용어가 장벽이 됩니다.
- 맞춤법과 띄어쓰기 교정. 이 스킬은 철자가 아니라 문장 골격을 봅니다.
- 한국어가 아닌 글, 그리고 시나 광고 카피처럼 목소리 자체가 목적인 글.

그리고 하나 더. **문체를 고칠 뿐 내용을 채우지 않습니다.** 할 말 없는 문단은 매끄럽고 짧은 빈 문단이 될 뿐입니다. 그럴 때는 다듬는 대신 그렇다고 말합니다.

3층 용어 분류의 경계는 시간이 지나면 움직입니다. `모델`과 `데이터`는 예전에 1층이었다가 2층으로 내려왔습니다. 소속 조직이나 투고 학회에 용어집이 있으면 그쪽이 먼저입니다.
