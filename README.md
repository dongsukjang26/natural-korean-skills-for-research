# natural-korean-skills

**자연스러운 한국어로 쓰는 Claude Code 스킬.** 번역투와 AI 문체를 걷어내고 한국어 어순으로 쓰게 합니다. 일상 설명과 AI 연구 문서, 두 모드로 나뉩니다.

*A Claude Code skill that makes Claude write Korean the way Koreans actually write it — with a separate mode for AI research writing, where technical terms stay in English.*

---

## 왜 필요한가

LLM이 쓴 한국어는 대개 문법이 틀리지 않습니다. 맞춤법 검사기를 돌려도 깨끗합니다. 그런데 읽으면 뻣뻣합니다.

> 이러한 변화는 효율성의 향상을 가져올 수 있습니다.

주어는 추상명사, 동사는 "가져오다", 목적어는 명사로 굳은 동작입니다. 영어 *This change can bring an improvement in efficiency*의 골격을 그대로 옮긴 문장입니다. 한국어를 모국어로 쓰는 사람은 이렇게 쓰지 않습니다.

> 이렇게 바꾸면 효율이 올라갑니다.

문제가 철자가 아니라 문장의 골격이라서 맞춤법 검사기로는 잡히지 않습니다. 골격은 다 쓰고 나서 고치는 것보다 쓰면서 잡는 편이 쌉니다.

AI 연구와 기술 문서에는 문제가 하나 더 붙습니다. 용어입니다. `attention`을 `어텐션`으로 적어 두면 문장은 한국어다워지지만 원문 논문과 이어지지 않고, 독자가 검색할 때 한 번 더 번역해야 합니다. 반대로 문장 골격까지 영어를 끌고 오면 이런 글이 됩니다.

> model을 3 epoch 동안 train했고, data는 clean한 subset만 썼다.

한국어 조사를 붙인 영어 문장입니다. 두 실패 사이에 선을 그어야 하고, 그 선이 이 스킬의 연구 모드입니다.

## 무엇을 근거로 만들었나

번역투 판정과 용어 분류를 취향으로 정하지 않으려고 다음 자료를 확인했습니다.

| 자료 | 무엇을 가져왔나 |
|---|---|
| [Google 머신러닝 용어집 한국어판](https://developers.google.com/machine-learning/glossary?hl=ko) | AI 용어를 영문 유지(ReLU, BERT, GAN, TPU), 한글 음차(어텐션, 임베딩, 레이어, 토큰), 한국어 번역(과적합, 손실, 정규화, 경사하강법) 세 갈래로 나눠 쓴다는 사실. 이 스킬의 **3층 용어 분류**가 여기서 나왔습니다 |
| [국립국어원 표준 전문용어와 다듬은 말](https://www.korean.go.kr/front/imprv/stndrdList.do?mn_id=159) | 중앙행정기관이 고시한 표준 전문용어와 외래어 한글 표기 기준. **2층(한글 음차)** 판단의 근거입니다 |
| [TTA 정보통신용어사전](https://terms.tta.or.kr/) | 국내 정보통신 분야 표준 용어 |
| [KatFishNet](https://arxiv.org/abs/2503.00032) (Park, Kim, Kim & Han) | 한국어 LLM 텍스트를 사람 글과 가르는 언어학적 지표로 **띄어쓰기, 품사 다양성, 쉼표 사용**을 지목한 논문. 쉼표를 절제하고 문장 리듬을 살피는 규칙이 여기 근거를 둡니다 |
| 국내 AI 기술 블로그와 논문 리뷰 글 | 실제 용법 관찰. "Attention 레이어", "LoRA", "loss 수렴", "SFTTrainer 클래스"처럼 영문 기법명 + 한글 음차 + 한국어 서술이 섞인 형태가 일반적입니다 |

한 가지 밝혀 둡니다. **Google 용어집은 attention을 음차(`어텐션`)로 적지만, 이 스킬의 연구 모드는 영문 유지(`attention`)를 택했습니다.** 용어집은 개념을 처음 배우는 독자를 향하고, 연구 모드는 원문 논문을 함께 읽는 독자를 향하기 때문입니다. 입문자에게 설명하는 글이라면 일반 모드 쪽이 맞습니다.

국내에 AI 분야 표기를 확정한 단일 표준은 없습니다. 3층 분류는 관행을 정리한 것이지 규범이 아닙니다.

## Before / After

### 일반 모드 — 개념 설명

| | |
|---|---|
| **Before** | 캐싱은 자주 사용되는 데이터를 미리 저장해 두는 기술입니다. 이를 통해 응답 속도를 향상시킬 수 있으며, 서버 부하 또한 감소시킬 수 있습니다. 결론적으로, 캐싱은 성능 최적화에 있어서 핵심적인 역할을 합니다. |
| **After** | 캐싱은 자주 쓰는 데이터를 미리 저장해 두는 기술입니다. 같은 데이터를 매번 다시 계산하지 않으니 응답이 빨라지고 서버도 덜 바쁩니다. 성능을 손볼 때 가장 먼저 꺼내는 카드죠. |

`~에 있어서`, `결론적으로`, `이를 통해`를 걷어내고 문장 길이를 섞었습니다. 긴 설명 뒤에 짧은 마무리가 오면서 리듬이 생깁니다.

### 일반 모드 — 오류 안내

| | |
|---|---|
| **Before** | 해당 오류는 의존성 버전 충돌에 의해 발생한 것으로 보여집니다. package.json을 확인하시어 버전을 통일해 주시기 바랍니다. |
| **After** | 의존성 버전이 서로 안 맞아서 나는 오류입니다. `package.json`에서 버전을 하나로 맞춰 보세요. |

`보여집니다`는 이중 피동이라 한국어 어문 규범에서 비문으로 봅니다. `~에 의해`는 영어 수동태의 직역입니다.

### 연구 모드 — 실험 결과

| | |
|---|---|
| **Before** | 본 실험에서는 어텐션 메커니즘에 기반하여 모델을 파인튜닝하였으며, 그 결과 베이스라인 대비 정확도가 향상되었음을 확인할 수 있었다. 이러한 결과는 해당 기법이 효과적임을 시사하는 바가 크다. |
| **After** | 이 실험에서는 attention 기반 모델로 fine-tuning을 했다. 정확도는 baseline보다 높았다. 이 기법이 통한다는 신호로 볼 만하다. |

음차한 용어를 영문으로 되돌리고 조사와 어미는 한국어로 두었습니다.

마지막 문장을 보세요. 원문의 `시사하는 바가 크다`는 확신을 다 주지 않는 표현이고, 고친 글의 `볼 만하다`도 같은 세기입니다. **"효과적이다"로 단언하면 다듬기가 아니라 다른 주장입니다.** 없던 수치도 넣지 않았습니다.

### 연구 모드 — 구현 노트

| | |
|---|---|
| **Before** | LLM을 활용하여 RAG 파이프라인을 구축하였고, 해당 파이프라인을 통해 검색 정확도를 개선할 수 있었습니다. 다양한 임베딩 모델들을 비교 실험한 결과, 한국어 데이터에 있어서는 multilingual 모델이 더 우수한 성능을 보여주었습니다. |
| **After** | LLM으로 RAG 파이프라인을 만들었더니 검색 정확도가 올랐다. embedding 모델 몇 개를 비교해 보니 한국어 데이터에서는 multilingual 모델이 더 정확했다. |

`LLM으로`의 조사를 보세요. 엘엘엠은 받침이 있으니 `으로`입니다. `GPU로`였다면 지피유에 받침이 없으니 `로`입니다. 영문 용어의 조사는 한글로 읽었을 때의 받침을 따릅니다.

더 많은 예시와 **고치면 안 되는 경우**는 [`examples/before-after.md`](examples/before-after.md)에 있습니다.

## 이 스킬이 하는 일

1. **모드를 고릅니다.** 사용자가 말하지 않으면 글의 종류로 판단하고, 고른 모드는 말하지 않습니다.
2. **한국어 어순으로 씁니다.** 영어 문장을 머릿속에서 옮겨 적지 않습니다. 옮겨 적은 문장은 나중에 되돌릴 수 없습니다.
3. **반드시 고치는 것을 고칩니다.** 이중 피동, `~에 있어서`, `가지고 있다`, 영어식 피동, 추상 주어 + 만능 동사, 명사화, AI 결말 관용구(`결론적으로`, `시사하는 바가 크다`), 조사 번역투 쏠림, `~적 N` 체인, 연결어미 뒤 쉼표, 3박자 반복. 전부 어느 어절이 어겼는지 손으로 짚을 수 있는 규칙입니다.
4. **판단이 필요한 것은 방향만 잡습니다.** 문장 리듬, 주어 생략, 지시어 절제, 복수 `-들`, 한자어 낮추기, 불릿 절제.
5. **사실을 바꾸지 않습니다.** 수치, 날짜, 고유명사, 인용문, 인과의 방향, **확신의 세기**를 그대로 둡니다. 읽기 좋아지려고 원인이나 빈도를 지어내면 다듬기가 아닙니다.
6. **기본 출력은 한국어 본문뿐입니다.** 모드 선언, 규칙 이름, 위반 건수를 붙이지 않습니다. "뭘 고쳤어?"라고 물으면 그때 before/after 표를 냅니다.

### 두 가지 모드

| | 일반 모드 | 연구 모드 |
|---|---|---|
| 독자 | 동료, 친구, 일반 사용자 | AI 연구자, 엔지니어 |
| 쓰는 글 | 대화 답변, 안내문, 개념 설명, 블로그 | 논문 정리, 실험 노트, 기술 문서, 코드 리뷰 |
| 영문 용어 | 꼭 필요할 때만. 한 번 쓰고 한국어로 풀어 줌 | AI 기술 용어는 영문 그대로 |
| 추측 표현 | 줄임. "~할 수 있습니다"를 단언으로 | **살림.** 불확실성은 연구 글에서 정보다 |
| 문장 길이 | 평균 12~15어절, 최대 25어절 | 평균 15~18어절, 최대 30어절 |

**두 모드가 다르게 처리하는 자리는 영문 용어와 추측 표현, 두 군데뿐입니다.** 나머지 규칙은 공통입니다. 그래서 모드를 잘못 골라도 글이 크게 망가지지 않습니다.

추측 표현이 가장 큰 차이입니다. 일반 모드에서 "성능이 개선될 수 있을 것으로 보입니다"는 자신 없는 말투로 읽히니 단언으로 바꿉니다. 연구 모드에서 같은 문장을 단언으로 바꾸면 실험이 보여주지 않은 것을 주장하게 되므로 그대로 둡니다.

### 용어 정책

연구 모드의 용어는 세 층으로 나뉩니다. 판단 기준은 하나입니다. **논문과 코드에서 그 형태로 쓰이는가, 아니면 한국어에 이미 들어온 말인가.**

| 층 | 표기 | 예 |
|---|---|---|
| 1층 | 영문 그대로 (연구 모드에서만) | transformer, attention, fine-tuning, loss, gradient, baseline, ablation, RAG, prompt, token, embedding |
| 2층 | 한글 음차 (두 모드 공통) | 모델, 데이터, 파라미터, 레이어, 벡터, 알고리즘, 라이브러리 |
| 3층 | 한국어 단어 (두 모드 공통) | 학습, 추론, 성능, 정확도, 가중치, 수렴, 실험, 평가, 한계 |

전체 목록, 조사 결합 규칙, 같은 단어가 두 뜻인 경우(`bias` 대 `편향`, `scale` 대 `규모`)는 [`references/ai-term-policy.md`](references/ai-term-policy.md)에 있습니다.

## 설치

### npx skills

```bash
npx skills add dongsukjang26/natural-korean-skills
```

```bash
git clone https://github.com/dongsukjang26/natural-korean-skills ~/.claude/skills/natural-korean-skills
```

`~/.claude/skills/`에 두면 모든 프로젝트에서 씁니다. 특정 프로젝트에서만 쓰려면 그 프로젝트의 `.claude/skills/`에 둡니다. `git pull`로 갱신됩니다.

## 사용법

한국어로 쓰거나 다듬어 달라고 하면 걸립니다.

```
이거 자연스러운 한국어로 설명해 줘
번역투 빼고 다시 써 줘
이 논문 내용 한국어로 정리해 줘
README 한국어로 써 줘
```

모드는 글의 종류를 보고 알아서 고릅니다. 직접 정하려면 이렇게 말하면 됩니다.

```
연구 모드로 정리해 줘
일반 모드로 쉽게 풀어 줘
```

기본 출력은 한국어 본문뿐입니다. 무엇을 고쳤는지 보려면 `뭘 고쳤어?`, `before/after 보여줘`, `어떤 규칙이야?`를 덧붙이세요.

## 범위와 한계

**맞습니다**: 한국어 설명과 답변, 문서, README, 기술 블로그, 연구 노트, 회의록. 영어 자료를 읽고 한국어로 정리하는 일. 번역투가 가장 많이 새어 들어오는 자리입니다.

**맞지 않습니다**: 맞춤법과 띄어쓰기 교정(이 스킬은 철자가 아니라 문장 골격을 봅니다). 완성된 글에 점수를 매기는 일. 한국어가 아닌 글. 시, 가사, 광고 카피처럼 목소리 자체가 목적인 글.

그리고 하나 더. **문체를 고칠 뿐 내용을 채우지 않습니다.** 할 말 없는 문단은 매끄럽고 짧은 빈 문단이 될 뿐입니다. 그럴 때는 다듬는 대신 그렇다고 말합니다.

3층 용어 분류의 경계는 시간이 지나면 움직입니다. `모델`과 `데이터`는 예전에 1층이었다가 2층으로 내려왔습니다. 소속 조직에 용어집이 있으면 그쪽이 먼저입니다.
